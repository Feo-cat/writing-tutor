# 评测工具与公开样例

`fact_checker.py` 是可选的事实核查模块。它先拆分陈述，对照素材判断置信度，再对需要核查的部分改写查询、检索证据并裁决。`checked` 表示是否依据检索证据判断；搜索失败、证据不足与模型输出故障分别记录，不能把没有查到当成陈述错误。

`run_eval.py` 对比两条路径：V1 直接判断陈述，V2 使用核查管线。结果分为标签是否符合金标准，以及独立评分模型是否认可理由。工具会核对模型设置、用例语义指纹和运行完整性；模型或题目变化后，旧基线可能不再可比。

## 本仓库包含什么

公开样例 `eval_cases.sample.json` 包含 12 条 dev 用例：公共知识与项目上下文各 6 条，每组的 correct、incorrect、unverifiable 各 2 条。它只验证格式与调用流程，不是效果基准，没有配套的完整 held-out 测试集。

样例中的 `daily-copilot-core` 是冻结的历史测试素材标识，题目围绕该段素材设计。它不是使用者的作者画像，也不是新项目的完整功能说明。为保持题目、金标准及指纹一致，本次没有改写这段测试材料。

`eval_manifest.json` 中的 `full_dataset` 记录旧完整题库的数量、分布、材料标识及 SHA-256，仅供历史核对。完整 120 条题库及原始结果没有迁入本仓库。`public_sample` 才对应仓库中实际存在的 12 条样例。不得将历史数量表述为新仓已附带 120 条题目。

## 如何检查

不调用真实服务的回归命令见 README。它们检查控制流、数据格式、评分工具和公开样例指纹，不证明模型写作或核查效果。

如果之后明确要进行真实评测，应先配置自己的模型服务，再指定不同的被测型号与评分型号，并显式选择公开样例：

```bash
EVAL_CASES_PATH=eval_cases.sample.json \
EVAL_SUT_MODEL=your-sut-model \
EVAL_GRADER_MODEL=your-grader-model \
uv run python run_eval.py --split dev
```

这是会访问模型和搜索服务的开发命令，可能产生费用；迁移阶段没有执行。真实结果默认写入 `local_artifacts/eval/results/`，不提交 Git。任何分享的结论都应说明样本数、实际模型、数据指纹及失败情况；12 条样例得分不能用于宣称完整评测效果。
