# Mac 运行验收

本步骤由运行机使用者执行，不要求修改代码或安装开发助手。请使用新项目的独立目录；原运行目录和备份继续保留。代码尚未交付到新 GitHub 仓库时，先不要在旧项目中执行这些步骤。

## 1. 核对版本与安装

进入新项目根目录，记录版本：

```bash
pwd
git branch --show-current
git rev-parse HEAD
git status --short --branch
sw_vers -productVersion
uname -m
```

如果有未提交代码修改，先停止并反馈。然后安装依赖：

```bash
uv sync --locked
cd web
npm ci
cd ..
bash verify.sh
```

预期：Python 检查通过，前端 lint 和 build 成功。检查中使用明确标注的测试回答与模拟模型，不访问真实模型或搜索服务；依赖安装会联网。失败时停在该步，反馈命令与错误输出，由开发机修改代码，不在 Mac 上手改代码。

## 2. 无配置页面

在没有 `.env`、也没有导出模型配置环境变量的新环境中执行 `bash run.sh`，浏览器打开 `http://127.0.0.1:8000`。

预期：网页能够打开，显示缺少密钥和模型，输入选题后“开始写作”仍禁用，没有假数据开关。点击“重新检查”只更新配置状态，不调用模型。现有作品可查看；全新目录中没有历史作品。

如果启动时已显示“配置已填写”，说明该环境已有配置，不能把这一轮当作无配置验收；先反馈，不删除或覆盖旧配置。

## 3. 真实写作

按 README 复制 `.env.example` 并填写自己的地址、密钥、模型，保存后 Ctrl+C 停止后台，再运行 `bash run.sh`。填写 API 密钥的内容只留在 Mac，不通过 Git 同步。

页面重新检查后，应显示配置已填写。以下步骤会产生真实模型请求，可能产生费用：

1. 输入一个新的简单选题，点击开始写作，等待素材和提纲。
2. 提纲应先停下来供确认；在开始问答前尝试填写修改意见并重排，确认新提纲后开始。
3. 由本人逐节回答，可以用 Shift+Enter 输入多行。确认编辑整理的是自己的回答。
4. 完成后检查初稿与终审，下载 Markdown。终审应为建议，不直接改正文。
5. 回到首页查看作品档案，检查初稿、问答和终审已保存。未配置网关账本时显示“未接入费用记录”，不是“花费为零”。

API 地址不可达、密钥无效或模型不支持所需协议时，应在页面看到提示。不要把“配置检查通过”单独当作模型兼容性通过。

## 4. 退出与反馈

按 Ctrl+C 停止后台，确认网页不再能发起新的后台请求。在项目目录运行 `git status --short --branch`，个人 `.env` 和写作产物不应出现在待提交清单中。

反馈：提交编号、执行到哪一步、通过或失败、相关错误输出。不要粘贴密钥、私人素材或文章正文。新配置和作品只属于这个独立目录；有问题时保留文件等待修复，不重置或删除原运行项目。
