# Mac 集中验收

每批修改交付后，用一个选题完成下面这轮检查，最后一次性反馈结果。不要把研究、提纲、第一轮教学拆成多次重复验收。代码修改和故障修复由开发机完成，Mac 只负责运行和反馈。

## 1. 更新并记录版本

停止后台，进入新项目 `writing-tutor` 的目录；旧项目目录与备份继续保留。先执行 `git status --short --branch`，如有未提交的代码修改，先保留并反馈，不强制覆盖。

工作区干净后执行一次更新与自动检查，命令链遇错即停：

```bash
git pull --ff-only origin main &&
uv sync --locked &&
(cd web && npm ci) &&
bash verify.sh &&
git rev-parse HEAD
```

预期出现 `Regression checks and frontend build completed.`。记录最后输出的提交号，与本批交付的目标版本核对；若不一致，先确认再测试。安装需要联网，自动检查不调用真实模型或搜索。

已完成的独立目录安装、无配置首页检查沿用已有记录，无需删除 `.env` 重新做。首次安装的使用者按 [README](../README.md) 操作；无配置检查应在填写密钥前确认首页可打开、缺项可见、开始写作被禁用，不要通过删除已有配置制造空环境。

## 2. 保持已验证的模型配置并启动

保留本机 `.env` 和作品，不重新复制样板覆盖。使用 DeepSeek 时核对 [配置项](deepseek.md#2-配置模型)，当前已成功生成大纲的建连等待为 `LLM_CONNECT_TIMEOUT_SECONDS=20`。本轮验证学习模式，`MAKINGOF_MATERIAL` 应留空；如要另测项目复盘，单独记录模式与输出文件。

```bash
bash run.sh
```

打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)，确认配置状态正常。读取配置状态不会验证密钥或模型权限；下面的写作步骤才会调用真实服务，可能产生费用。

## 3. 用一篇短文章检查完整流程

选一个自己熟悉的小话题，使用未写过的选题名称，避免复用旧素材和草稿。提纲出来后，可以提交“缩成两个短节，每节只讲一个概念”的重排意见，在同一篇文章中完成提纲修改检查；节数由模型实际返回为准。

| 步骤 | 需要确认的结果 |
|---|---|
| 研究与提纲 | 能生成可读素材和提纲；抽查一条来源能否打开、是否支持相关要点。搜索日志出现查询不代表结果一定有效 |
| 修改与确认提纲 | 修改意见能够影响新提纲；重排只调用策划，不重新搜索。确认前不会直接进入问答 |
| 导师问答 | 每节先讲再问，由本人作答后得到正常反馈。观察逐字显示、点击显示全文，以及 Enter 发送、Shift+Enter 换行 |
| 编辑与终审 | 初稿包含各节内容，以自己的回答为依据，没有编造个人经历；终审给建议，不直接改写正文 |
| 下载 | “下载初稿 .md”能得到可打开的文件，正文与页面初稿一致；终审意见在页面和本地审稿文件中另行查看 |

逐节完成即可，不要求为每个按钮重新生成一篇文章。过程中不要刷新或关闭页面：未完成对话的恢复不在本轮承诺范围内。

遇到错误就停在失败步骤，记录页面提示与相关日志，不为收集所有错误反复发起真实模型请求。无效配置、空输出、截断和工具上下文等已有自动检查；本轮不要求人为制造故障。模型输出降级或保存失败不能记为完整通过。

## 4. 检查保存和重启后的档案

全文完成并下载后，在后台按 Ctrl+C 停止，再用 `bash run.sh` 启动。重新打开首页，从作品档案进入刚才的文章；只查看已有作品，无需再点“开始写作”。

确认学习模式保存了素材、提纲、问答、初稿和终审意见，自己的回答仍在。默认文件位于 `local_artifacts/blogs/`。未配置网关账本时应显示“未接入费用记录”，不能把未知费用显示成零。

检查完停止后台，在项目根目录执行：

```bash
git status --short --branch
git check-ignore .env local_artifacts/blogs/
git ls-files -- .env local_artifacts/
```

默认配置下，状态应没有新增待提交文件，`check-ignore` 列出上述两个私有位置，`ls-files` 无输出。自定义目录时另外核对实际位置；不回传文件内容。若作品缺失或未被忽略，保留现状并反馈。

## 5. 一次性反馈

```text
版本：完整提交号
环境：macOS 版本 / 芯片架构（若与此前一致可写“同前”）
自动检查：通过 / 失败
研究与提纲、修改提纲：通过 / 失败 / 未测
导师、编辑与终审：通过 / 失败 / 未测
下载、保存、重启后档案：通过 / 失败 / 未测
Git 状态与私有目录忽略：正常 / 异常
问题：失败步骤、页面提示、相关错误行
```

不要附密钥、完整 `.env`、私人素材或文章全文。结果对应本次提交，不以服务启动成功或大纲成功代替全流程通过。首次发现故障由开发机集中修复，复测优先覆盖失败步骤及受影响的后续环节。
